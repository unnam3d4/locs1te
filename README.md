# БАЗА ДАННЫХ ИТСО

Локальное приложение для работы с таблицами, картами оборудования, файлами, поиском и рабочим чатом. Интерфейс выполнен в классическом стиле Windows 98 SE. Проект развивается по согласованному техническому заданию.

> **Статус: первая проверяемая версия (MVP), не окончательный релиз.** Часть утверждённых функций ещё не реализована. Не используйте этот прототип как единственное хранилище рабочих данных.

## Быстрый запуск исходников

На компьютере-сервере (в том числе Windows 7 **SP1**) нужен Python **3.8**. В исходной версии сторонние библиотеки для сервера не требуются.

1. В командной строке в каталоге проекта запустите `py -3.8 server.py --init-admin` (либо `python server.py --init-admin`) и придумайте пароль администратора.
2. Запустите `py -3.8 server.py` и откройте `http://127.0.0.1:3000`.
3. Чтобы разрешить доступ со второго компьютера, определите **локальный IP серверного ПК** и запустите `py -3.8 server.py --host 192.168.1.50` с **реальным** адресом этого ПК. Разрешите порт 3000 в брандмауэре Windows **только для частной LAN**. С другого ПК зайдите по `http://<IP_сервера>:3000`.
4. Для добавления редакторов и наблюдателей на серверном ПК используйте `py -3.8 server.py --add-user`. Для ручного резервного копирования — `py -3.8 server.py --backup-now`.

На Windows данные по умолчанию сохраняются в `C:\ITSO_DB\data`. На Linux/macOS для проверки — в каталоге `data` текущей папки. Для другого пути есть `--data-dir`.

**Безопасность:** по решению владельца используется обычный HTTP без TLS. Пароли и данные **не шифруются при передаче по LAN**. Не публикуйте порт в интернете, не настраивайте проброс портов и работайте только в доверенной локальной сети. Не загружайте реальные служебные данные в **публичный GitHub-репозиторий**. Локальные данные исключены через `.gitignore`.

## Что уже работает

- HTTP-сервер на стандартной библиотеке Python и SQLite WAL; при первом запуске не создаются оборудование, карты и таблицы.
- Учетные записи `admin`, `editor`, `observer`; пароли PBKDF2-HMAC-SHA256 с солью; серверная проверка ролей и CSRF; сеанс 2 часа.
- Создание пустых карт и таблиц; раздельные ревизии ячеек и объектов — одновременное изменение одной записи приводит к HTTP 409 вместо тихой перезаписи.
- Таблица: ввод значений, жирное начертание, заливка; базовая сетка.
- Карты: создание объектов с произвольными характеристиками, перетаскивание, прямые соединения, ручной PING. Без автоматических проверок.
- «Обменник»: один список, потоковая загрузка без программного лимита, **возобновляемая загрузка по блокам 1 МиБ с подтверждением смещения**, сохранение одноимённых файлов как независимых, скачивание с поддержкой HTTP Range; удаление файлов только администратором.
- Чат: отправка всем ролям, исправление своего сообщения за 15 минут, удаление администратором.
- Общий текстовый поиск по значениям ячеек, свойствам объектов, названиям файлов и сообщениям; поиск по словам, фильтр раздела, страницы по 50.
- Ручное резервное копирование и периодическое ежечасное копирование SQLite через backup API; вложения сохраняются в резервных точках, по возможности через жёсткие ссылки; срок 14 дней на том же диске.

## Продолжение загрузки больших файлов

В разделе «Обменник» браузер загружает файлы блоками по 1 МиБ. Если сеть оборвалась, сервер запоминает подтверждённое смещение. После восстановления соединения и повторного выбора **того же локального файла** загрузка продолжится с подтверждённой позиции. Идентификатор незавершённой загрузки запоминается браузером локально, содержимое файла — нет. Если блок доставлен, но ответ потерялся, при новом запросе проверяется состояние на сервере. Повторное подтверждение завершённой загрузки не создаёт второй файл. Оставленные более семи дней незавершённые загрузки очищаются автоматически во время часового обслуживания. Общий размер файла программно не ограничен; ограничение 2 МиБ действует только на отдельный сетевой блок.

Протокол для тестов и интеграции: `POST /api/uploads` (JSON `{name,size}`), `GET /api/uploads/<id>` (состояние), `PUT /api/uploads/<id>` (двоичные данные, заголовок `X-Upload-Offset`), `POST /api/uploads/<id>/finish` (подтвердить завершение). Удаление незавершённого файла — `DELETE /api/uploads/<id>`. Все операции требуют входа, изменения защищены CSRF; состояние и запись доступны только отправителю. Старый `POST /api/files` пока сохранён для совместимости.

## Конструктивные решения

- База `itso.db` и файлы лежат **локально на серверном ПК**, а не в общей сетевой папке.
- Никаких предустановленных типов оборудования, именованных карт или обязательных характеристик.
- Сеансы фиксированной длительности: два часа, без долговременного автоматического входа.
- Права на чтение данных проверяются сервером. Наблюдатель может писать в общий чат и загружать файлы, но не редактирует карту/таблицу.
- Не сохраняем пользовательский журнал действий, только диагностику с минимальным объёмом.
- Загрузка файлов не блокируется заранее из-за низкого остатка диска, но ошибка недостатка места должна явно возвращаться пользователю.

Файлы в этом репозитории — **исходники первого этапа**, а не готовая сборка `ITSO_Запуск.exe`.


## Этап 3: расширенная версия исходников (22.10.2026)

Реализованы серверные API и базовые элементы интерфейса для переименования, копирования и удаления таблиц/карт, CSV-импорта и экспорта (без сохранения расширенного форматирования), .itmap-импорта/экспорта и PNG, ручных контрольных точек карты, привязок оборудования к ячейкам таблиц в обе стороны, файловых вложений у оборудования и в чате, счётчика непрочитанных, истории 20 поисковых запросов. Добавлены полный архив SQLite + файлы с SHA-256, восстановление при остановленном сервере и тесты.

Подготовлены `windows/itso_service.py` (Windows Service), `windows/admin_panel.py` (локальная панель управления с учётными записями и копиями), `windows/ITSO_Install.nsi` и `windows/BUILD_WINDOWS.bat` (сборка Windows EXE и NSIS-установщика). На целевом Windows-компьютере требуется Python 3.8 на время СБОРКИ и NSIS 3 для установщика; после упаковки в PyInstaller клиентские ПК не требуют Python. **Собранный и проверенный установщик не вложен в репозиторий.**

Для исходной версии полный экспорт (локально): `python server.py --export-archive C:\\ITSO_backup.zip`, восстановление **при остановленном сервере**: `python server.py --restore-archive C:\\ITSO_backup.zip`. Оба действия требуют учётные данные администратора текущей базы. **Восстановление заменяет данные**; сохраняйте копию архива вне серверного компьютера.

Объект карты может быть простым оборудованием/условным изображением стены, двери или окна. Это не завершённый CAD-подобный редактор планов помещений. `.itmap` содержит объекты и линии, но НЕ переносит вложения/внешние изображения (их следует переносить полным архивом базы). При копировании карты существующие связи с таблицами намеренно не копируются.

**Оставшиеся существенные задачи:** проверенная Windows 7–11 сборка, мастер установки и полевые испытания; профессиональная таблица с XLS/XLSX, листами, объединением ячеек и настройкой размеров; полноценные слои, редактируемые подложки, размеры помещений и линии со свободными концами; оптимизация поиска для больших баз и push-синхронизация двух клиентов без периодического обновления; комплексная проверка полного диска, сетевых обрывов и восстановления после отключения электричества. Утверждённые требования остаются целевыми, но эти функции НЕ реализованы полностью.

В исходных файлах сохранён обычный HTTP без шифрования по решению владельца. Категорически не открывайте порт во внешний интернет.
